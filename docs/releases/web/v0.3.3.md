### 更新摘要

- 重构 iCloud 隐藏邮箱账号、地址创建和邮件阅读体验，支持从一个入口完成账号设置、
  候选地址预览及最多 5 个地址的批量创建。
- 优化工作区导航与缩放场景：侧栏头尾固定、中间菜单独立滚动，并将 iCloud 入口移动
  到垃圾箱之后。
- 将完整 HTTP API 参考扩展为可自动生成、可验证的分类 Markdown 文档。

### 新增

- iCloud 账号列表中的每个账号增加独立设置入口，可修改备注名称、更新 Cookie、更新
  iCloud 邮箱和应用专用密码。
- 新增 `PATCH /api/icloud/accounts/{id}`，按当前用户归属更新账号备注并记录审计日志。
- 创建隐藏邮箱前显示 Apple 生成的候选地址，并支持“换一个”；预览与最终保留地址使用
  同一个不透明 `previewId`，保持 Apple `generate` / `reserve` 会话连续性。
- 支持一次创建 1–5 个隐藏邮箱，每个项目可填写独立标签；中途失败时已成功项目立即
  同步，未创建项目留在弹窗中继续处理。
- 新增 `POST /api/icloud/aliases/preview`，旧客户端未传候选地址时仍保留单次生成并创建
  的兼容路径。
- 新增 `docs/api/` 完整分类 API 参考：9 个业务分类、102 个端点、认证要求、请求参数、
  成功响应、注意事项和 cURL 示例。
- 新增 `npm run docs:api`，从应用内 API Catalog 确定性生成 Markdown 文档。

### 改进

- 5 个隐藏邮箱创建项目在桌面端使用两列紧凑卡片，移动端自动恢复单列；“换一个”和
  “移除”改为带无障碍名称与悬浮说明的 44×44 图标按钮。
- iCloud 凭据保存成功提示统一改为固定 toast，不再插入弹窗内容造成高度变化和闪动。
- iCloud 邮件发件人拆分为名称和地址；识别 Hide My Email 中继地址后显示友好说明，
  原始中继地址保留在悬浮标题中，不进行不可靠的反向猜测。
- iCloud 导航入口移动到垃圾箱之后；移动端可直接进入，不再绕经账号设置。
- 侧栏顶部品牌/主题区与底部账号区固定，仅中间导航滚动；滚动条与邮件列表使用同一
  套悬停、滚动显示和延迟隐藏行为。
- 移除应用内 Cloudflare 自动更新构建接口；发现新版本后引导管理员在 GitHub Fork
  页面执行 **Sync fork → Update branch**，再由 Cloudflare 重新部署。

### 安全与兼容

- iCloud 账号备注更新同时按账号 ID 和当前用户 ID 过滤，其他用户无法读取或修改。
- Cookie 和应用专用密码继续在 Worker 内加密保存，查询接口只返回配置状态，不回传
  原值。
- 候选隐藏邮箱限制为有效 `@icloud.com` 地址，并要求地址与 UUID 格式的 `previewId`
  成对提交；无效输入不会请求 Apple。
- 批量创建仍复用现有单地址 API 顺序执行，避免并发预览导致 Cookie 或 Apple 客户端
  状态竞态。

### API 文档

- `docs/API.md` 保留架构、安全、限速和数据生命周期说明，并链接完整分类参考。
- 生成文档写入 Catalog 元数据指纹；测试会同时校验真实 Worker 路由、应用内目录、
  Markdown 端点标记和说明/参数/示例元数据。
- 当前 API 总数保持 102：移除两个自动更新构建接口，新增账号备注更新和隐藏邮箱预览
  接口。

### 升级说明

- 无需新增 D1 迁移、Worker 变量、Secret、R2、Queue 或 Workflow 绑定，正常重新构建并
  部署即可。
- 部署脚本不会自动执行 Vite build；发布前必须先运行 `npm run build`，再执行
  `wrangler deploy`。
- 旧部署以后通过 GitHub Fork 同步获取版本，不再在应用内直接启动 Cloudflare 构建。
