# OmniMail Android 实施计划

## 产品边界

这是 `E:\\go\\new\\OmniMail` 的原生 Android 客户端，不是 IMAP/SMTP 客户端。
数据、权限、搜索、发信和邮件文件继续由用户自己的 OmniMail Worker、D1 与 R2 提供。

## 技术基线

- Kotlin、Jetpack Compose、Material 3、单 Activity
- Android API 36 / AGP 8.13 基线；Core 1.17 与 Lifecycle 2.10 为当前兼容组合
- 单向数据流：Compose → ViewModel → Repository → OmniMail HTTP API
- 手机采用单栏逐级导航；中等宽度采用列表 + 阅读器；展开宽度采用导航 + 列表 + 阅读器
- Access Token 仅驻留内存；Refresh Token 使用 Android Keystore 加密
- 服务端游标用于当前会话翻页，服务端 `version` 用于低成本条件刷新

## 里程碑

截至 `android-v0.3.0`，M1 已完成；M2 的 Room 缓存、离线只读、条件后台同步和分页已完成；
M3 的搜索、批量操作、草稿、发信、回复、转发、附件上传下载已完成；M4 的新邮件通知、
深链、无障碍基础与签名发布流程已完成。后续继续补充设备管理和更完整的截图矩阵。

### M1：可登录、可阅读

交付：实例配置、设备令牌登录/轮换/退出、邮箱地址、邮件列表、邮件详情、已读与星标、
手机/平板自适应布局、错误与空状态。

验收：

1. `testDebugUnitTest` 与 `assembleDebug` 通过。
2. Access Token 过期后只刷新一次，并原子替换本地 Refresh Token。
3. 360dp 宽度无水平滚动；840dp 以上同时显示文件夹、列表和阅读器。
4. 令牌、密码和邮件正文不进入日志。

### M2：离线与同步

交付：Room 元数据缓存、最近邮件纯文本缓存、WorkManager 条件同步、网络恢复重试、分页。

验收：飞行模式可打开最近缓存；恢复网络后不重复邮件；账号退出清除本地邮件数据。

### M3：完整日常邮件操作

交付：搜索、批量操作、草稿、发信、回复、附件上传/下载、系统文件选择器。

验收：所有发送请求使用幂等键；附件限制与服务端一致；失败操作可明确重试。

### M4：系统集成与发布

交付：新邮件通知、深链、后台刷新策略、账号/设备管理、无障碍与大字体 QA、签名发布流程。

验收：通知不泄露敏感正文（默认仅显示发件人）；TalkBack 主流程可用；手机和平板截图测试通过。

## 继续保持在客户端之外

- 管理员的用户、域名、备份、部署与审计后台
- 通讯录、转发、邮件规则（服务端当前也不提供）
- 在客户端直接配置 Cloudflare 或发信服务 Secret
- HTML 远程图片自动加载

## 后端兼容与安全

Android 继续沿用当前 `/api/*`。`android-v0.3.0` 已通过显式客户端类型申请最小权限
设备令牌，并在刷新旧的全权限 Android 会话时只做向下收紧。后续版本化 API 仍建议补充：

- 明确的机器可判定错误码，避免客户端依赖中文错误文案；
- 增量同步游标或变更日志，而不只是列表版本号；
- 可选 FCM 桥接订阅接口；当前版本使用 WorkManager 条件轮询，不依赖 Google 服务。
